# Loca 要件定義 (3) MAP 関連機能

> 移植元: Loca システム要件定義書 3章。

## 3. MAP関連機能

### 3.1. 初期表示・検索モード
* **初期状態**:
    * Google MAPを表示する。
    * 表示範囲: 表示位置と縮小サイズは、クライアントのディスプレイサイズに日本列島が画面に収まる大きさとする。
    * サイドメニューは「検索モード」、地図/マーカーのトグルを表示する。
* **地図の制限**:
    * 縮小と移動に制限をかけ、世界地図以外が表示されないようにする。
* **トグル動作**:
    * **「地図」選択時**: 検索文字を入力し、**「検索」ボタン**を押下することでAPI送信を行い、地図を移動させる。
    * **「マーカー」選択時**: 検索文字を入力し、**「検索」ボタン**を押下することで、合致する登録済みマーカーのみを抽出する。
    * **結果表示**:
        * マーカー検索結果の一覧は、地図上の**「共通結果パネル（オーバーレイ）」**に表示する。
        * **UI挙動（モバイル）**: スマートフォン（モバイルビュー）での操作時、**検索実行ボタンを押下したタイミングでサイドメニューを自動的に閉じる（非表示にする）**。これにより、限られた画面領域で結果パネルと地図の視認性を確保する。
        * **検索ロジック**: ランキング機能とはプログラムを分け、表示件数制限（ページネーションや100件制限）を**適用しない**。
        * **スクロール仕様**: 合致した**すべてのマーカー**を表示し、パネル内を**縦スクロール**可能にする。

#### 3.1.3. 🗺️ 地図上での範囲指定検索機能 (新規)

**目的**: ユーザーが地図上に描画した特定の矩形領域内にあるマーカーのみを抽出できるようにする。

| 項目 | 要件定義 |
| :--- | :--- |
| **機能名称** | 地図上範囲指定検索（Geo-Fence Search） |
| **起動トリガー** | 検索モードのサイドメニュー内、既存の検索フィールドの下に**「範囲指定モードを開始」ボタン**を新設し、これをクリックすることでモードを起動する。 |
| **UI挙動** | 1. 範囲指定モード起動後、地図操作カーソルが**十字線**に変化する。2. 地図上で**マウスダウン**（またはタップ/長押し）した座標を始点とし、**マウス移動**（またはドラッグ）した際に、始点と現在座標を結ぶ**透明な矩形（長方形）**をリアルタイムで描画する。 |
| **描画完了** | マウスアップ（指を離す）した時点で描画を完了し、**検索処理を自動で実行する**。描画された矩形は、検索結果表示中も地図上に維持される。 |
| **検索ロジック** | データベース上のマーカーの**緯度・経度**が、描画された**矩形領域の境界内**に完全に含まれるマーカーのみを抽出する。 |
| **検索結果の表示** | 抽出されたマーカーは、既存の「**共通結果パネル（オーバーレイ）**」に一覧で表示される。検索ロジックは既存の`3.1.`の「マーカー検索」に準じ、**件数制限は設けない**。 |
| **検索後の状態** | 検索結果が表示された後も、サイドメニューは検索モードを維持し、描画された矩形は**地図上に残ったまま**とする。 |
| **クリア機能** | 検索モードのサイドメニュー内に**「範囲指定をクリア」ボタン**を新設し、押下時に描画された矩形を地図上から削除する。矩形が削除された後、**地図上のすべてのマーカーが再表示される**（フィルタが解除される）。 |
| **他検索との排他** | 範囲指定モードがアクティブな状態、または矩形が描画されている状態では、既存のテキスト入力による「地図/マーカー検索」フィールドは**非活性化（グレーアウト）**する。範囲指定をクリアした後にテキスト検索が利用可能になる。 |

### 3.2. 登録・編集フロー
* **登録モード**:
    * **トリガー**: 地図をクリックすると「仮マーカー」が表示され、サイドメニューが「登録モード」（登録/キャンセルボタン表示）になる。
    * **未認証時の挙動**: 地図をクリックしてもモード遷移せず、検索モードを維持する。
    * **登録実行**: 「登録」クリックでマーカーを保存。
    * **キャンセル**: 「キャンセル」クリックで仮マーカーを解除し、検索モードに戻る。
* **編集モード**:
    * **トリガー**: 既存マーカーをクリックすると「編集モード」（更新/削除/キャンセルボタン表示）になる。
    * **未認証時の挙動**: 既存マーカーをクリックしてもモード遷移せず、検索モードを維持する。
    * **削除権限**: 管理者またはそのマーカーを登録したGoogleアカウントユーザーのみ削除可能。この「削除」操作は、`1.4. マーカーデータ読み込みのリアルタイム・ハイブリッド化`で定義された**論理削除（Soft Delete）**として実行される。
* **共通挙動**:
    * **地図クリック制御**: 仮マーカー表示中に地図内を再クリックしても、地図画面（中心位置）は移動させない。
    * **GPS入力連動**: **登録前または既存マーカーの編集中**において、GPS項目を手動編集した際は、仮マーカー位置と地図画面を移動させる。
    * **仮マーカーの自動削除**: **地図と登録/編集モードのサイドメニュー以外の箇所をクリックした場合**（例：ランキングタブへの切り替え、結果パネルの閉じるボタン、地図上のインフォウィンドウ外など）、**仮マーカーを削除**し、サイドメニューを**検索モード**に戻す動作とする。
    * **仮マーカーの表示色**: 登録前または編集中に地図上に表示される**仮マーカーの色は、感情タグの設定にかかわらず一律でグレー**とする。

### 3.3. 入力項目・バリデーション
* **入力項目（計8項目）**と**UI配置順**:
    1. Youtube URL (必須)
    2. **行動への影響 (Actionable Intent) (必須)**
    3. **動画の雰囲気 (Atmosphere/Vibe) (必須)**
    4. **感情の核 (Core Emotion) (必須)**
    5. GPS (緯度・経度の2つのテキストフィールド)
    6. 撮影機器 メーカー
    7. 撮影機器 シリーズ
    8. 撮影機器 モデル
* **感情タグのUI仕様**:
    * 感情タグは以下の3つの大カテゴリに分け、それぞれを**ラジオボタン形式（排他選択）**の簡易なUIで実装する。
    * **大カテゴリ（行動への影響、動画の雰囲気、感情の核）はすべて必須項目**とし、ユーザーは**各カテゴリから一つのみ**を選択できる（**複数選択不可**）。

| UI配置順 | 大カテゴリ | 選択肢（タグ） |
| :--- | :--- | :--- |
| **2** | **行動への影響 (Actionable Intent)** | 訪問/地域紹介, 映像制作, お祭り/イベント, 機器/技術紹介 |
| **3** | **動画の雰囲気 (Atmosphere/Vibe)** | 明るい(Positive), 真面目(Serious), 落ち着いた, 緊張, 幻想的, スマート |
| **4** | **感情の核 (Core Emotion)** | 喜び, 興奮, 癒し, 驚き, 恐怖, 悲しみ, 希望 |

* **マーカーの登録色（感情の核に基づく）**:
    * 登録済みのマーカーは、登録時に選択された**「感情の核 (Core Emotion)」のタグの色**を反映して表示する。

| 感情の核 (Core Emotion) | マーカー色 | 色の定義 |
| :--- | :--- | :--- |
| **興奮** | **赤色** | 活発、エネルギー |
| **喜び** | **オレンジ色** | 非日常、ミステリアス |
| **希望** | **黄色** | 明るさ、未来 |
| **癒し** | **緑色** | 自然、平穏 |
| **悲しみ** | **青色** | 深さ、共感 |
| **驚き** | **水色** | 非日常、ミステリアスな感情を表す新しい色 |
| **恐怖** | **紫色** | 緊張、暗さ |

* **バリデーション**:
    * Youtube URLとGPS入力に対し、不正な入力（数字以外、範囲外座標など）をチェックし、違反時はメッセージを表示する。
    * **Youtube URLの重複チェック**:
        * 登録モード、および編集モード（編集中でないURLの場合）において、入力された**Youtube URLが、すでに他のマーカーとしてデータベースに登録されていないか**をチェックする。
        * **重複が検出された場合**は、登録・更新処理を中断し、ユーザーにその旨を伝える**エラーメッセージを表示**する。
* **GPS項目の編集可否**:
    * 既存マーカーの**編集モード**において、**GPS（緯度・経度）の入力フィールドは編集可能**とする。ユーザーが値を変更し、**更新ボタン**を押すことで、データベースに新しいGPS情報が反映されること。
* **撮影機器UI制御**:
    * 初期状態はすべて"未選択"。
    * メーカーが選択されるまで、シリーズとモデルのプルダウンはグレーアウト（無効化）する。
    * メーカー選択後に次の項目が選択可能となるフィルタ（誤った組み合わせ防止）を実装する。

### 3.4. API連携・データ保存（登録時）
* **自動取得データ**:
    * Youtube URLと位置情報をもとに、以下のAPIを使用しデータを取得する。
    * **Youtube API**: サムネイル, Title/Channel Title, Published At, View Count, Like Count, Comment Count, Duration
    * **Google MAP API**: 都道府県, 市町村
* **登録条件**: 両方のAPIから応答があった場合のみ登録する。
* **データ変換**: 動画の長さ（Duration）はISO 8601形式から**「秒単位の整数値」**に変換して保存する。
* **エラーハンドリング（ポップアップ表示）**:
    * **Google MAP API失敗**: 「地図情報（都道府県・市町村）の取得に失敗しました。この場所は登録できませんでした。**(Google MAP APIエラー）」
    * **Youtube API失敗**: 「動画情報（再生数など）の取得に失敗しました。URLまたは動画が非公開になっていないか確認してください。**(Youtube APIエラー）」
    * **両方失敗**: 「動画情報および地図情報の取得に失敗しました。URLまたは位置情報を確認してください。**(両APIエラー）」

### 3.5. インフォウィンドウ（閲覧時）
* **表示内容**: 動画サムネイル、再生数、チャンネル名の3項目を表示し、Youtubeへ遷移可能にする。
* **表示挙動**:
    * 既存マーカークリック時に地図上に表示。
    * 他の地図位置をクリックすると非表示になる。
    * 別のマーカーをクリックすると、既存のものを閉じ、新しいマーカーのインフォウィンドウを表示する（排他表示）。

### 3.6. ユーザーマーカー一覧画面からの地図ジャンプ機能
Google認証済みのユーザーが、画面右上のユーザーアイコンクリック後に遷移する**「自分のマーカー一覧画面」**において、地図上へのジャンプ機能およびUI制御を以下の通り実装する。

* **ジャンプ機能の動作（単一選択時）**:
    * **条件**: 一覧内のレコードが**1つのみ**選択（チェックボックスなどでマーク）されている状態であること。
    * **トリガー**: 活性化された**「地図へジャンプ」ボタン（仮称）**を押下する。
    * **アクション**:
        1.  地図画面に遷移し、選択されたレコードに対応する**マーカーが地図の中心**となるように移動（パン）させる。
        2.  マーカーが明確に視認できる**適切な縮尺サイズ**（例：ズームレベル14～16程度）に自動的に調整（ズーム）する。
* **UIボタンの制御（複数選択・未選択時）**:
    * **機能名**: 上記のアクションを実行するためのUIとして**「地図へジャンプ」ボタン（仮称）**を配置する。
    * **複数選択時**: 選択されているレコードが**2つ以上**の場合、このボタンは**非活性化（グレーアウト）**する。
    * **未選択時**: レコードが**1つも選択されていない**場合、このボタンは**非活性化（グレーアウト）**する。
    * **注記**: 複数選択時および未選択時、ボタンは**非表示ではなく、必ず非活性状態（グレーアウト）を維持**すること。

### 3.7. 既存マーカー詳細表示と編集制御
* **マーカー情報表示モード**:
    * **トリガー**: 既存のマーカーをクリックした時。
    * **アクション**: サイドメニューを**「マーカー情報表示モード」**に遷移させ、そのマーカーの**登録情報**および**APIで取得した情報**（Youtube情報、地図情報など）を一覧表示する。この表示は、登録や編集のための入力フォームではなく、情報の**閲覧に特化した形式**とする。
* **ボタンの表示制御**:
    * **更新・キャンセルボタンの表示**: 閲覧中のマーカーが、**現在ログインしているユーザー自身が登録したマーカー**である場合のみ、「**更新**」および「**キャンセル**」ボタンをサイドメニュー内に表示する。
    * **登録者以外の表示**: 現在ログインしているユーザーが**登録者以外**である場合、サイドメニューに「更新」および「キャンセル」ボタンは**一切表示しない**（閲覧のみに限定する）。

### 3.8. ⚠️ マーカー通報機能 (新規)

**目的**: 悪意または不適切なマーカーをユーザーが管理者へ報告できる仕組みを設ける。

| 項目 | 要件定義 |
| :--- | :--- |
| **通報ボタンの配置** | 既存マーカークリック時に表示される**インフォウィンドウ（3.5.）**、または**マーカー情報表示モード（3.7.）**のサイドメニュー内の**視認性の高い位置**に「**通報**」ボタンを配置する。 |
| **起動トリガー** | 「通報」ボタンをクリックすると、**通報理由を選択する**モーダルウィンドウ（ポップアップ）を表示する。 |
| **通報理由の選択肢** | 以下の5つの悪意あるパターンを**チェックボックス形式（複数選択可）**で提示する。1. **著作権侵害、または登録者本人以外の動画URLの登録。** 2. **公序良俗に反する、または法令に違反する内容の動画URLの登録。** 3. **動画の内容とマーカーの登録位置が著しく異なり、誤認を誘発している。** 4. **不正確な情報や虚偽の情報を意図的に拡散する目的での登録。** 5. **不適切な個人情報や誹謗中傷など、第三者への嫌がらせを目的とした情報を含む。** |
| **詳細記述** | 選択肢の下に、**自由記述のテキストエリア**を設け、ユーザーが通報内容を詳細に記述できるようにする（任意入力）。 |
| **データ保存** | 通報実行時、以下の情報をFirestoreまたは専用のログシステムに記録する。<ul><li>通報されたマーカーのID</li><li>通報を実行したユーザーのID</li><li>選択された通報理由（複数可）</li><li>自由記述の内容</li><li>通報日時</li></ul> |
| **通報後の挙動** | 通報が完了したことを示すメッセージをユーザーに表示する。通報されたマーカーは、管理者が対応を完了するまで**一般ユーザーには引き続き表示される**状態とする。 |

## Loca での扱い（移植時の差分）

| 元の要件 | Loca での実現 |
|---|---|
| Google MAP を表示 | `MapPort` を定義。MapLibre GL JS + 地理院タイル（API キー不要・予備なし。ADR 0011）。Google Maps は請求先アカウントが必須のため使わない |
| Google MAP API で都道府県・市町村を取得 | `GeocodePort`。国土地理院の逆ジオコーダ＋市町村コード表（キー不要・予備なし。ADR 0011）。政令指定都市は区を落として市まで |
| YouTube API でサムネイル等を取得 | `VideoMetaPort`。既定は `oembed`（キー不要だが再生数は取れない）、`youtube`（Data API・全項目）、`fixture`（完全オフライン） |
| 両 API から応答があった場合のみ登録 | 維持。失敗パターン 3 種のメッセージも要件どおり（`src/app/useMarkerSubmit.ts`） |
| 矩形範囲指定検索 | 維持。MapLibre / Google Maps の両アダプタに実装 |
| 仮マーカーは一律グレー | 維持（`NEUTRAL_HEX`） |
| 感情の核でマーカー色を決定 | 維持（`src/core/constants/emotion.ts`） |

**注意**: 国土地理院の地名 API は非公式で、予告なく変わりうる。海上と県境未定地（富士山頂など）では
地名を取得できず、登録は地名なしで続行する。
