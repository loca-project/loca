# 0004. 静的 JSON を一次ソースにする

- 状態: 採用
- 日付: 2026-09-22

## 背景

要件 1.4 が「ベースデータ（静的 JSON）＋ リアルタイム差分」というハイブリッド構成を求めている。
元の狙いは API コストの削減だったが、Loca ではこれを**可用性の土台**としても使う。

## 決定

`public/data/markers.json` を一次ソースとして扱う。

- 形式: `{ "generatedAt": <epoch ms>, "markers": [...] }`
- 生成: `scripts/build-markers-json.mjs`（Node のみ。cron / GitHub Actions / Cloud Scheduler から呼べる）
- 論理削除済み（`deleted: true`）は出力しない
- ローカルアダプタは初回起動時にこれを IndexedDB へ取り込む。`generatedAt` が
  前回より新しいときだけ再取り込みするので冪等

## 結果

良くなること:

- バックエンドが落ちていても地図とランキングが成立する。
- 配信先が決まる前でも、静的ファイルだけで公開デモが出せる。
- 初期表示が速い（購読の確立を待たない）。

悪くなること:

- データが二重になる。`markers.json` とバックエンドの間に最大 1 日のずれが出る。
  これは差分購読で埋める前提。
- バッチが止まると静的データが古びる。失敗時は非ゼロ終了するので、
  呼び出し側で 15 分間隔・3 回までの再試行と通知を設定すること。
