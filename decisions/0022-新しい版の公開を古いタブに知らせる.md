# 0022. 新しい版の公開を、開いたままの古いタブに知らせる

- 状態: 採用
- 日付: 2026-09-25
- 関連: [0010](0010-書き込みと認証にFirebase無料プランを使う.md)、[0020](0020-セキュリティルールを部品に分けて生成する.md)

## 背景

本番に出すときは、Firestore のルールを先に反映してからコードを公開する（新しい画面の書き込みが旧ルールで拒否されないため）。
そのため、公開前に開いたタブは古い JS のまま新しいルールに書き込み、拒否されうる。
2026-09-24 の本番確認で、ニックネームの変更が実際にこれで拒否された。
SPA は読み直すまで古い JS で動き続け、GitHub Pages の index.html は 10 分キャッシュされる。

## 決定

1. ビルドが `dist/version.json` に **入口の JS のファイル名**（例 `assets/index-XXXX.js`）を書く（`vite.config.ts`）。
2. 画面は、自分が読み込んだ入口と `version.json` を比べ、違えば画面上部の帯で「新しい版があります」と
   「再読み込み」のボタンを出す（`src/runtime/version.ts`・`HealthNotice`）。
3. 比べるのは次の 3 つの機会だけ。
   - 10 分ごと（index.html のキャッシュと同じ間隔）
   - タブに戻ったとき（前回から 1 分以上空いたとき）
   - Firestore の書き込みが `permission-denied` で拒否されたとき
4. 自動では再読み込みしない。入力の途中で画面が消えるのを避け、利用者に押してもらう。
5. `npm run verify` が、`version.json` の版と `index.html` の入口の一致を確かめる。

## 検討した代替案

- **コミット SHA を版にする**: 毎晩の同期はデータのコミットを作って公開し直すので、コードが同じでも毎晩案内が出る。却下。
- **Service Worker で更新を検知する**: 仕組みが大きく、キャッシュの不整合という別の障害を持ち込む。却下。
- **拒否されたら自動で再読み込みする**: 入力中の内容が消える。却下。

## 影響

- ルールだけを先に反映してから公開されるまでの 1〜2 分は、古いタブの書き込みが拒否されても案内は出ない（`version.json` がまだ古い）。
  公開後の最初の確認（タブに戻る・次の拒否・10 分後）で案内が出る。
- 開発サーバー（`/src/main.tsx`）では入口が `assets/` に無いので、確認しない。
