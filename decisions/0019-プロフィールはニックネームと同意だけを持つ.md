# 0019. プロフィールはニックネームと同意の記録だけを持つ

- 状態: 採用
- 日付: 2026-09-24
- 関連: [0010](0010-書き込みと認証にFirebase無料プランを使う.md)、[0012](0012-Firestoreのデータ形とルールの方式.md)、[0014](0014-タグを人にしか書けない情報に絞る.md)

## 背景

要件 2.5.1 はプロフィール登録で国籍・生年月日・性別を必須にしている。一方で要件 1.1 は「データを最大限保存しない」とし、
T26 の題は「ニックネーム・同意日時・Google ID」だった。投稿者名はプロフィールが無いため、uid から作る仮の名前（`user-xxxxxx`）だった。

## 決定

1. **プロフィールは `users/{uid}` に置く。** uid は Firebase Auth の uid なので、Google アカウントに紐づく（利用者の判断）。
   画面には連携中の Google アカウント（写真・名前・メール）を見せるが、それは Firebase Authentication が持つ値で、Firestore には保存しない。
2. **持つのはニックネーム・同意の版・同意日時・登録日・更新日時だけ。** 国籍・生年月日・性別は集めない（利用者の判断）。
3. ニックネームは 1〜20 字・改行なし・前後の空白なし。マーカーの投稿者名（`createdBy`）として公開する。
   Google の名前は本名のことが多いので公開しない。
4. 同意は 3 項目（権利を持つ動画だけ・現地で撮った実写だけ・保存と公開の目的）。全部に印が付くまで登録できない。
   「現地で撮った実写」は ADR 0014 の決定 6 のとおり、投稿ごとではなく初回に 1 回だけ取る。
   文面を変えたら `CONSENT_VERSION` とルールの `consentVersion` を上げて取り直す。
5. **未登録の利用者はマーカー・撮影リクエスト・通報を作れない。** ルールが `users/{uid}` の存在を確かめる。
   マーカーの `createdBy` はルールがプロフィールのニックネームと一致することを確かめる。
6. 初回ログインで登録画面を出し、閉じさせない。「キャンセル」はログアウトする。
7. 変えられるのはニックネームだけ。**既存のマーカーの投稿者名は変わらない**（`createdBy` は作成後に変えられない。ADR 0012）。
8. プロフィールを読めるのは本人と管理者だけ。削除は当面管理者だけ（本人の削除は T54）。

## 検討した代替案

- **要件 2.5.1 どおり国籍・生年月日・性別を集める**: 統計に使えるが、使い道の決まっていない個人情報を持つことになる。利用者の判断で却下。
- **投稿者名を表示のたびにプロフィールから引く**: 名前の変更がすぐ反映されるが、プロフィールを誰でも読めるようにするか、
  毎晩の同期で名前を配る仕組みが要る。作成時の値を残す形にした。
- **YouTube の権限（youtube.readonly）でチャンネルを自動で連携する**: sensitive scope の可能性があり（未確認）、
  Google の審査が済むまで「未確認のアプリ」の警告が出る。チャンネル URL の手入力と一致のバッジにした（T55）。

## 結果

- 本番で試験データを投稿していた人は、次のログインで登録画面が出る。試験データは `/reset-data` で消す（投稿者名が `user-xxxxxx` のまま残るため）。
- マーカーの作成・撮影リクエスト・通報のルールで、読み取りが 1〜2 回増える（`exists` と `get`）。

## 確かめ方

`npm run test:rules` の `tests/rules/users.test.mjs` と `tests/store/profileStore.test.mjs` がすべて通る。
