# 0007. 地図に maxBounds を設定しない

- 状態: 採用
- 日付: 2026-09-22

## 背景

要件 3.1 に「縮小と移動に制限をかけ、世界地図以外が表示されないようにする」とあり、
MapLibre の `maxBounds` に全世界（-180〜180, -85〜85）を渡していた。

公開後、**地図が灰色一色で何も描画されない**状態になった。

## 調査で分かったこと

同一ページを `maxBounds` あり／なしで比較して測定した。

| | center | zoom | タイル取得 |
|---|---|---|---|
| `maxBounds` あり | **[180, 35.64]** | **20** | 1 件 |
| `maxBounds` なし | [134.45, 35.64] | 4.56 | 28 件 |

`maxBounds` に経度の全範囲（360 度ぶん）を渡すと MapLibre の制約計算が破綻し、
**中心が経度 180 度（太平洋上）・ズームが最大値**に飛ばされる。
そこには描画すべきデータが無いのでタイルが 1 枚も要求されず、背景色だけが残る。

## 決定

**`maxBounds` を設定しない。**

要件の意図（世界の外側の空白を見せない）は次の 2 つで足りる。

- `minZoom: 3` … これ以上引けない
- `renderWorldCopies`（MapLibre の既定 true）… 横方向は世界が繰り返されるので空白が出ない

## 結果

- 地図が正しく日本列島を表示するようになった。
- 横方向には世界が繰り返される（Google マップと同じ挙動）。要件の意図には反しない。
- 一部の領域だけに限定したくなった場合は、全世界ではなく**その領域の矩形**を
  `maxBounds` に渡すこと。全範囲を渡してはいけない。

## この不具合を見逃した理由と再発防止

自動確認が DOM の文字列とピンの数しか見ていなかった。
**マーカーは HTML 要素なので、地図が真っ白でも描画されて「OK」になる。**

`scripts/smoke.mjs` を追加し、**地図タイルが実際に取得されたか**を数えて判定するようにした。
公開前に `npm run smoke` を実行する。
