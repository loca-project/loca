# 0008. Issue フォームの項目は input で作る（dropdown を使わない）

- 状態: 採用
- 日付: 2026-09-22

## 背景

感情タグ 3 種を Issue フォームの `dropdown` で定義していた。選択式のほうが
入力ミスが減ると考えたため。

公開後、**サイトで選んだ値が Issue に反映されない**ことが判明した。
URL・緯度・経度（`input`）は入るのに、タグ 3 種だけが「None」のままだった。

## 原因

**GitHub の Issue フォームは、クエリパラメータで `input` と `textarea` しか
事前入力できない。** `dropdown` と `checkboxes` はパラメータを無視する。

Loca の投稿は「サイトで入力 → 事前入力済みの Issue フォームを開く」という流れなので、
事前入力できない型を使うと、利用者が同じ内容を 2 回入力することになる。

## 決定

**事前入力したい項目はすべて `input` にする。**

- 感情タグ 3 種（行動への影響・動画の雰囲気・感情の核）→ `input`
- 熱量 → `input`
- 選択肢は `description` に列挙して案内する
- 値の妥当性は取り込み時（`scripts/lib/validate.mjs`）に厳密に検査し、
  外れていれば Issue にコメントして差し戻す

**同意チェック（確認事項）は `checkboxes` のまま残す。**
事前入力できないのはむしろ正しい。同意は本人が能動的に行うべきもので、
勝手にチェック済みにしてはいけない（要件 2.5.3）。

## タイトルについて

GitHub の Issue はタイトルが必須で、これは消せない。
利用者に書かせないよう、**アプリ側で自動生成してクエリパラメータで渡す**。

- マーカー: `[marker] 東京都 港区 / 動画タイトル`
- リクエスト: `[request] 35.6586, 139.7454 熱量3`
- 通報: `[report] 対象の動画タイトル`

一覧で見分けがつくので、承認作業もしやすくなる。

## 再発防止

`npm run verify` に 2 項目を追加した。

1. Issue フォームの項目が事前入力できる型か（`agreement` を除き dropdown / checkboxes を禁止）
2. フォームの見出しが取り込み側の対応表（`validate.mjs`）に揃っているか

実際に `dropdown` に戻して検証が落ちること（`NG marker.yml:tag-action=dropdown`）を確認済み。
