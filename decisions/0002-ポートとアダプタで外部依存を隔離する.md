# 0002. ポートとアダプタで外部依存を隔離する

- 状態: 採用
- 日付: 2026-09-22

## 背景

Chronos MAP を Loca として移植するにあたり、公開先のプラットフォームが決まっていない。
移植元は Firebase（認証・DB・ホスティング）と Google Maps に密結合しており、
`App.tsx` から直接 `services/firebase.ts` を呼んでいた。この形のまま移すと、
別のプラットフォームに載せ替えるときに画面コードまで書き換えることになる。

また「ローカルのブラウザで動作確認できること」という要求がある。
Firebase と Google Maps はどちらも鍵と課金設定が要るため、そのままでは満たせない。

## 決定

インターフェース（ポート）と実装（アダプタ）を分け、起動時に選択する。

- `src/ports/` にインターフェースを置く。`src/core/` の型だけに依存する。
- `src/adapters/` に実装を置く。**外部 SDK を import してよいのはここだけ**。
- `src/runtime/container.ts` が環境変数を見てアダプタを解決する。
- `src/features/` と `src/core/` からの SDK 直接 import は `npm run verify` で禁止する。

各ポートの最後の候補は、**外部依存ゼロで必ず成立する実装**にする
（data=local, auth=local, map=maplibre, video=fixture, geocode=offline, semantic=keyword）。

## 結果

良くなること:

- 配信先が決まっても本体のコードを変えずに済む。変えるのは `.env` と `deploy/` だけ。
- 鍵なしでローカル動作確認ができる。
- バックエンドが落ちたときに縮退運転へ自動で切り替わる（冗長性）。
- 外部サービスをモックせずにロジックを試せる。

悪くなること:

- 間接層が 1 枚増え、ファイル数が増える（46 → 約 90）。
- ポートが最小公倍数になるため、特定サービス固有の最適化（Firestore の複合クエリ等）を
  そのままでは使えない。必要になったらアダプタ内に閉じた拡張として足す。

## 代替案

- **Firebase のまま移植する**: 実装は速いが、移植性の要求を満たさない。却下。
- **BaaS を抽象化するライブラリを使う**: 依存が増え、そのライブラリ自体が移植性の足枷になる。却下。
