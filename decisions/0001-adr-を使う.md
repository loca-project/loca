# ADR 0001: 設計判断を ADR として記録する

- 状態: 採用
- 日付: （記入する）

## 背景

設計上の判断は、決めた直後は自明でも、数か月後には理由が失われる。
Claude Code のセッションは毎回コンテキストがリセットされるため、
「なぜこの設計なのか」が残っていないと、過去に検討して却下した案が再提案される。

## 決定

設計上の判断を `project/decisions/NNNN-短い題名.md` に記録する。
番号は連番、ファイル名は日本語でよい。

## 書式

各 ADR は次の節を持つ。

- **背景** — 何に困っていたか。制約は何だったか
- **決定** — 何を選んだか（能動態・断定で書く）
- **検討した代替案** — 他に何を見て、なぜ落としたか
- **結果** — この決定によって何が容易になり、何が難しくなったか

## 検討した代替案

- **コードコメントに書く**: 複数ファイルにまたがる判断を置く場所がない。
- **`docs/` に混ぜる**: 「現在の仕様」と「過去の判断」が混ざり、どちらが最新か分からなくなる。
- **記録しない**: 同じ議論を繰り返す。却下。

## 結果

- 良くなる点: 過去の判断理由を Claude に読ませて、再検討の出発点にできる。
- 面倒になる点: 判断のたびに1ファイル書く手間がかかる。小さな判断まで ADR にしないこと。
