# 0009. サイト上での GitHub 認証は見送る

- 状態: 置き換え（[0010](0010-書き込みと認証にFirebase無料プランを使う.md)）
- 日付: 2026-09-22

## 背景

次の 5 つが要望として挙がった。

1. サイト上で GitHub 認証を行い、右上を「ログイン」にする
2. 「投稿」を押したら画面遷移せず、裏で Issue を作成する
3. メニューをプルダウンにまとめる
4. 管理者に指定されたアカウントに「管理者機能」を出す
5. 管理者を初期登録し、後から管理画面で追加できるようにする

このうち **1・2・4・5 はすべてサイト上の認証が前提**になる。

## 調査でわかったこと

ブラウザだけで GitHub 認証を完結できるかを確認した。

| 方式 | client_secret | ブラウザから呼べるか | 判定 |
|---|---|---|---|
| OAuth web flow | 必要 | CORS 非対応 | 不可 |
| Device Flow | 不要 | **CORS プリフライト非対応** | 不可 |
| GitHub App の SPA 対応（PKCE） | 不要 | CORS 対応 | **Preview かつ Paused** |

3 つ目は本来これが答えだが、GitHub のロードマップ上で提供が止まっている。
つまり**現時点で確実に認証を実装するには、トークン交換を担うサーバーが要る**。

これは [ADR 0005](0005-GitHubだけで完結させる.md) の「サーバーを 1 台も持たない」前提を崩す。

## 決定

**認証は導入しない。項目 3（メニューのプルダウン化）のみ実装する。**

- 投稿は従来どおり「事前入力済みの Issue フォームを開く」方式を維持する
- 管理者機能（項目 4・5）は作らない。統計とエクスポートは公開データの集計なので、
  認証なしで誰でも見られる状態のまま問題ない
- GitHub App の SPA 対応が正式提供されたら再検討する

## 実装したこと（項目 3）

右上に 5 つ並んでいたボタン（最新バッジ・言語・統計・ヘルプ・リポジトリ）を、
1 つの「メニュー」プルダウンに集約した。

- 地図が隠れる面積が減った
- 認証を導入するときは、このプルダウンの最上段に「ログイン」を足せばよい
- `RuntimeBadge.tsx` は廃止し、`DataFreshness.tsx` としてプルダウン内の 1 行にした

## 再検討するときの判断材料

導入する場合の選択肢は 2 つ。

| 方式 | 長所 | 短所 |
|---|---|---|
| Cloudflare Workers に中継を置く | 標準的で確実。無料枠で足りる | サーバーと秘密が 1 つ増える |
| 個人アクセストークンを貼り付ける | サーバー不要 | 一般利用者に重い。トークン保管のリスク |
