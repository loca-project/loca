# 0018. 撮影機器を「分類 → メーカー → シリーズ → モデル」の 4 段にする

- 状態: 採用
- 日付: 2026-09-24
- 関連: [0014](0014-タグを人にしか書けない情報に絞る.md)、[0015](0015-地図フィルタを画面下に常設する.md)

## 背景

移植元の撮影機器は「メーカー → シリーズ → モデル」の 3 段で、マスタには DJI・Zero Zero Robotics・Sony の 3 社しか無かった。
ドローンを前提にした並びで、次の問題があった。

- 同じメーカーの中に種類の違う機器が混ざる（DJI の Mavic はドローン、Osmo Action はアクションカム、Osmo Pocket はジンバルカメラ）。
- 「ドローンで撮った動画」「スマートフォンで撮った動画」のように、種類で探す手段が無い。
- スマートフォンやアクションカムで撮る人が、選べる機器を持たない。

## 決定

1. **最上段に汎用の分類を置き、「分類 → メーカー → シリーズ → モデル」の 4 段にする**（利用者の判断。モデルは残す）。
2. 分類は 9 つ。値は英小文字のキーで保存し、表示は ja / en の語に置き換える（ADR 0014 のタグと同じ方式）。

   | キー | 日本語 | English |
   |---|---|---|
   | `drone` | ドローン | Drone |
   | `mirrorless` | ミラーレス・一眼 | Mirrorless / DSLR |
   | `cinema` | シネマカメラ | Cinema camera |
   | `action` | アクションカム | Action camera |
   | `gimbal` | ジンバルカメラ | Gimbal camera |
   | `camera360` | 360度カメラ | 360° camera |
   | `smartphone` | スマートフォン | Smartphone |
   | `camcorder` | ビデオカメラ | Camcorder |
   | `other` | その他 | Other |

3. 同じメーカーが複数の分類に出てよい（DJI はドローン・アクションカム・ジンバルカメラ）。
4. **分類だけ（メーカーは未選択）でも登録できる。** マスタに無い機器で撮った人も、種類は残せる。
5. マスタの元データは `scripts/data/equipment-master.mjs` に置き、`npm run data:equipment` で `public/data/equipment.json` を作る
   （`public/data/*.json` は手で編集しない規約のため）。管理者画面で直した分類は Firestore に置き、同期が `equipment.json` に反映する（ADR 0025 で改訂）。
   `npm run data:equipment` はコードの既定だけで作るので、画面で直した分類は次の同期まで既定に戻る。
6. 分類のキーは src・ルール・マスタの 3 か所にある（ADR 0025 で 5 か所に増えた）。`npm run verify` が一致を検査する。
7. 地図フィルター（ADR 0015）に機器の分類を足す。動画だけに効く（撮影リクエストの絞り込みは季節・時間帯・撮り方のまま）。

## 検討した代替案

- **分類 → メーカー → シリーズの 3 段（モデルを捨てる）**: 入力は 1 つ減るが、機種の情報が失われる。利用者がモデルを残すことを選んだ。却下。
- **分類をタグ（ADR 0014）に足す**: 機器の階層と二重に持つことになる。却下。

## 結果

- 機器の型に `category` が増え、ルールは 4 項目すべてを求める（分類は一覧のキーか空文字）。
  旧形式（分類なし）のマーカーは表示できるが、更新すると分類の項目が付く。地図フィルターで分類を選ぶと当たらない。
- 登録フォーム・撮影リクエスト・機器別ランキングは、同じ部品（`EquipmentSelects`）で 4 段を選ぶ。
- 機器別ランキングの行は「メーカー / シリーズ / モデル」のまま。分類だけの機器はランキングの行にならない。

## 確かめ方

`npm run verify` の「機器の分類が src・ルール・マスタで一致」が OK で、機器別ランキングで分類を選ぶと、その分類のメーカーだけが出る。
