# 0005. データベースと認証を持たず、GitHub だけで完結させる

- 状態: 一部置き換え（書き込みと本人確認は [0010](0010-書き込みと認証にFirebase無料プランを使う.md)）
- 日付: 2026-09-22
- 置き換え: [0002](0002-ポートとアダプタで外部依存を隔離する.md) の一部（複数バックエンドの差し替えは不要になった）

## 背景

配信先を GitHub Pages に決定し、Google API と Firebase の利用を廃止した。
データベースと認証は「決定を見送り」となり、
**使わずに機能を維持できるならその方向で設計し直す**という方針になった。

閲覧・検索・ランキングは静的 JSON だけで完全に成立する。
問題は書き込み（マーカー投稿・撮影リクエスト・通報）で、これには
共有される可変状態と本人確認が要る。

## 決定

**GitHub 自体をデータベースと認証基盤として使う。**

| 必要なもの | GitHub の何で代替するか |
|---|---|
| データの保存 | リポジトリ上の `project/public/data/*.json` |
| 書き込みの受付 | Issue フォーム（`.github/ISSUE_TEMPLATE/*.yml`） |
| 本人確認 | GitHub アカウント |
| 検証・反映 | Actions（`ingest-issue.yml`） |
| 承認フロー | メンテナが `approved` ラベルを付ける |
| 監査ログ | git の履歴と Issue |
| レートリミット | GitHub 側の制限 |

アプリ側に書き込み用のポートは作らない。
`features/contribute/issueUrl.ts` が Issue フォームの URL を組み立てるだけで、保存はしない。

## 結果

良くなること:

- 運用するサーバーが 0 台。落ちる対象も、課金も、鍵の管理も無い。
- 誰がいつ何を追加したかが git の履歴に残る。改竄も追跡できる。
- 承認を挟めるので、不適切な投稿が地図に載る前に止まる。
- 認証実装がゼロになった（`AuthPort`・プロフィール画面・セッション管理をすべて削除）。

悪くなること:

- **投稿に GitHub アカウントが要る。** 一般利用者には敷居が高い。
- **反映まで数分かかる。** 即時性が必要な機能は作れない。
- **いいねは実装できない。** 1 クリックごとに Issue を立てるのは現実的でないため、
  機能ごと削除した。将来 Issue のリアクション数を集計する手はある。
- メンテナの承認作業が運用コストとして残る。

## 代替案

- **Supabase 等の BaaS**: 即時反映といいねが可能。ただし 7 日で停止する無料枠の制約と、
  外部サービス依存が増える。「使わずに済むなら使わない」という方針に反する。却下。
- **完全に閲覧専用**: 実装は最小だが、コミュニティマップでなく作品集になる。却下。
- **ブラウザ内保存のみ**: 投稿 UI は残るが他人に見えない。中途半端。却下。

データベースが必要になったら、`CatalogPort` に実装を足し、
書き込み用のポートを新設する形で後から導入できる。
