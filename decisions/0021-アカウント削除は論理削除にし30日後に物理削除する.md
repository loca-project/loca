# 0021. アカウント削除は論理削除にし、30 日後に Actions が物理削除する

- 状態: 採用
- 日付: 2026-09-24
- 関連: [0013](0013-同期より後の変更はupdatedAtで表す.md)、[0017](0017-YouTube-Data-APIとFirestoreへの書き込みはActionsから行う.md)、[0019](0019-プロフィールはニックネームと同意だけを持つ.md)

## 背景

要件 2.7 は、アカウント削除ですべての情報を「永続的に削除する」としている。
一方で ADR 0013 は、利用者に物理削除させないと決めている。
物理削除した行は `updatedAt` の差分の購読に届かず、地図を開いている人には次の同期まで古い姿が残るからである。
管理者の物理削除も、同期を手で走らせないと公開データとずれる。

## 決定

1. **アカウント削除は論理削除で行う**（利用者の判断）。画面が次の順に進める。
   1. Google で本人確認する（`reauthenticateWithPopup`）。取り消したら何もしない。
   2. 本人のマーカーをすべて `deleted: true` にし、動画の索引を外す（禁止の印が付いた索引は残す）。
   3. 撮影リクエストをすべて取り下げる（熱量は戻る）。
   4. プロフィールと名前の索引を消す。
   5. ログインの登録（Firebase Authentication の利用者）を消す（利用者の判断）。
2. 2〜4 は、途中で失敗してももう一度実行すれば残りから続く。途中の画面では登録画面を割り込ませない。
3. ルールに次を足す。
   - 本人が `deleted` を true にするだけの更新は、レートリミットの印なしで通す（まとめて消すため）。
   - 本人はプロフィールを消せる。プロフィールを消す同じバッチで、名前の索引も手放せる。
4. ログインの登録を消すので、同じ Google アカウントで入り直すと新しい uid になる。以前の投稿とは紐づかない。
5. **物理削除は、論理削除から 30 日たった行だけを、毎晩の同期のあと Actions が行う**（利用者の判断。T58）。
   - 対象はマーカー・撮影リクエスト（取り下げ済み）と、それを指す動画の索引。
   - 公開データにはもう含まれない行なので、差分の購読と公開データの件数は変わらない。
   - 30 日は、誤操作と通報の調査のための猶予。
6. **管理者画面（T27）の削除も論理削除だけにする。** 物理削除は 5 の仕組みに一本化する。
7. 通報（`reports`）は運営の記録として残す。熱量とレートリミットの印（`heatBudgets`・`rateLimits`）は数字だけなので残す。
   （2026-09-25 追記）炎の集計（`answerCounts`。ADR 0028）も残す。受け取ったリクエストが 30 日後に消えても炎は減らない。消えたマーカーの分は T66 で扱う。

## 検討した代替案

- **要件 2.7 どおりその場で物理削除する**: 地図を開いている人に削除が届かない（ADR 0013）。
  ルールに本人の物理削除を許す例外も要る。却下。
- **自動の物理削除をせず、管理者が手で消す**: 消し忘れが残り、同期の手動実行も要る。利用者の判断で却下。
- **ログインの登録を残す**: メールアドレスが Firebase Authentication に残り、「利用登録履歴からの削除」を満たさない。却下。

## 結果

- 確認画面には「30 日間は管理者だけが見られる形で残り、そのあと完全に消去する」と書く。
- 物理削除は `sync-firestore.yml` の `purge` ジョブ（`scripts/purge-deleted.mjs`）。計画は `scripts/lib/purge-plan.mjs`。
  - 消すのは「30 日前」と「公開データの `syncedAt`」の早いほうより前に消された行だけ。
  - 読んだあとに変わった行（管理者の復元など）は消さない（`updateTime` の前提条件）。
  - 実行の記録は `jobs/purge-deleted`。手元では `npm run data:purge`（`--dry-run`）で計画だけを見られる。
- アカウント削除 1 回で、マーカーの数だけ書き込みが増える（3 件ずつのバッチ。ルールの `get`・`exists` の上限に収めるため）。

## 確かめ方

`npm run test:rules` の `tests/rules/accountDeletion.test.mjs` と `tests/store/accountDeletion.test.mjs`、
`npm run test:scripts` の `tests/scripts/purge-plan.test.mjs` がすべて通る。
ログインの登録の削除はエミュレータの外なので、本番で確かめる。

## 追記（2026-09-25 いいね。ADR 0024）

- 撮影リクエストの取り下げの後に、**付けたいいねをすべて外す**手順が入った（件数が減る）。再実行で続くのは 2〜5（プロフィールの削除まで）。
- 付けたいいね 1 件ごとに、いいねと件数の 2 件を書くトランザクションも増える。
- 外したいいね（`deleted: true`）と消えたマーカーのいいね・件数は、まだ 30 日後の物理削除の対象に入っていない（T66）。
