# 0028. 撮影リクエストへの回答は、依頼者が受け取ったときに炎をマーカーへ移す

- 状態: 採用
- 日付: 2026-09-25
- 関連: [0016](0016-参加の循環を撮影リクエストへの回答で作る.md)、[0024](0024-いいねの件数は集計文書に置き付けた人は公開しない.md)、[0013](0013-同期より後の変更はupdatedAtで表す.md)、T43・T82

## 背景

ADR 0016 の「頼む → 応える → 届きました」を作る。Cloud Functions が使えないので、投稿者の書き込みで依頼者の熱量を戻すことはできない
（熱量の印 `heatBudgets/{uid}` は本人と管理者しか書けない）。
また、応えた数をプロフィールで見せたい（T82）。熱量は戻るたびに使い直せるので、ユーザー単位の残りの熱量からは数えられない。

## 決定

1. **応える**: 撮影リクエストの地点から動画を登録すると、マーカーに `answers`（その地点の、ほかの人の未取り下げのリクエスト ID。1〜10 件）が付く。
   作成のときだけ付けられ、あとから変えられない（管理者は外す向きだけ変えられる）。
2. **届いたことを知らせる**: 依頼者のブラウザが、公開データと差分の購読で手元にあるマーカーから、自分のリクエストを `answers` に持つものを探して出す。
   読み取りは増えない。
3. **受け取るかは依頼者が決める**（利用者の判断）。「受け取る」を押すと、リクエストを取り下げ（`answeredBy` にマーカー ID）、熱量の印を減らし、
   `answerCounts/{markerId}` に炎（そのリクエストの熱量）と件数 1 を足す。3 つを 1 つのトランザクションで書き（同時の受け取りは読み直して再試行。ADR 0024 と同じ）、ルールが互いを確かめる。
   受け取ったリクエストは地点の熱量から消え、依頼者の熱量は戻る。受け取るまでは地図に残り、ほかの人も応えられる。
4. **炎はマーカーの側に貯める**（利用者の提案）。`answerCounts = { heat, count, ownerUid, last }`。誰でも読める。
   投稿者の合計は公開プロフィールに、動画ごとの炎はマーカー情報に出す（T82）。合計は、`where ownerUid == uid` で投稿者の文書を読み、
   いま地図にある動画の分だけを足す（削除した動画の分は数えない。利用者の判断）。
   受け取ったリクエストは論理削除なので 30 日後に物理削除される（ADR 0021）が、炎はマーカーの側に残る。
5. 自分のリクエストに自分の動画で応えても、受け取れない（ルールが拒む）。
6. **受け取れるのは、リクエストから 3 時間以上たって登録され、地点の近く（緯度・経度とも 0.01 度以内。約 1 km）にある動画だけ**（ルールの `answerable`）。
   物理削除のあと同じ ID で作り直して二重に受け取る・遠い場所の動画で「届きました」を偽るのを防ぐ。画面の「届いた動画」も同じ条件で出す。
   3 時間の待ちは、2 つのアカウントで炎を増やす速さを抑えるため（利用者の判断。はじめ 1 日としたが、機器の同期の間隔とそろえて 3 時間にした）。
   出してから 3 時間たたないリクエストは、応える対象にも入れない。

## 検討した代替案

- **受け取ったリクエストを数える**（`answeredOwnerUid` を付けて count）: 30 日後の物理削除で数が減る。却下。
- **マーカーの文書に炎を書く**: マーカーは本人と管理者しか書けず、書くと `updatedAt` が進んで差分の購読が全員に流れる。却下。
- **応えた時点で熱量を戻す**: 依頼者の望んだ映像か分からないまま戻ってしまう。利用者の判断で「受け取ったら戻す」。

## 結果

- マーカーの項目に `answers` が増え、公開データ（`markers.json`）にも載る（依頼者のブラウザが探すため）。
- `answerCounts` は `reset-data` で消す（試験データ）。消えたマーカーの分の扱いは `likeCounts` と同じ（T66）。
- `answerCounts` は `updatedAt` を持たないので、差分の購読には乗らない（開いたときに読む。ADR 0024 の `likeCounts` と同じ）。
- 読み取りは、マーカー情報を開くたびに 1 件（その動画の炎）、公開プロフィールを開くたびに、いいね・炎の付いたその投稿者の動画の数だけ増える（T82）。
- 公開プロフィールの合計は、いま地図にある動画の分だけ（削除した動画の分は数えない。利用者の判断）。
- マーカーのルールは式の数が 1000 個の上限に近い。軽い更新（投稿者名をそろえる・本人の論理削除）を先に、通常の更新を最後に並べた。
- 2 つのアカウントで頼む・応える・受け取るを繰り返せば炎は増やせるが、3 時間の待ちで、熱量 5 の一巡が 3 時間に 1 回までに抑える（決定 6）。

## 確かめ方

依頼者と投稿者の 2 アカウントで「頼む → 応える → 届きました → 受け取る」が一巡し、依頼者の熱量が戻り、地点の熱量が減り、
その動画の炎が受け取ったリクエストの熱量だけ増える。ルールは `tests/rules/answers.test.mjs`。
